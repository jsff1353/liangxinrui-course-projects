# 校园智能二手交易平台 — 项目文件功能说明

> 用途：答辩讲代码结构、写论文第 5 章「系统实现」时按包/文件对照查。
> 工程根目录：`D:\桌面\1`
> 后端：`campus-trade-backend`（Spring Boot 3.2.5 + MyBatis-Plus 3.5.7 + MySQL 8）
> 前端：`campus-trade-frontend`（Vue 3.4 + Vite 5 + Element Plus 2.7 + axios）

---

## 一、整体分层

| 层 | 技术 | 目录 | 职责 |
| --- | --- | --- | --- |
| 表现层 | Vue 3 SPA | `campus-trade-frontend/src/views` | 页面渲染、表单校验、交互 |
| 接口层 | axios 封装 | `campus-trade-frontend/src/api` | 统一 baseURL `/api`、带 token、拆包 |
| 控制层 | Spring MVC | `com.campus.trade.controller` | 收参数、@Valid 校验、调 service、包 `Result` |
| 业务层 | Service | `com.campus.trade.service(.impl)` | 业务规则、权限、事务、状态机 |
| 数据层 | MyBatis-Plus | `com.campus.trade.mapper` + `entity` | 单表 CRUD 与条件构造 |
| 横切 | 拦截器 / 全局异常 / 定时任务 | `interceptor` `common` `task` | 鉴权、统一错误、超时订单回收 |

一次请求的固定链路：

```
浏览器 → vite proxy(/api) → JwtInterceptor(preHandle 解析 userId + 管理员校验)
      → Controller(@Valid 校验 DTO) → ServiceImpl(业务)
      → Mapper(MyBatis-Plus) → MySQL
      → Result{code,msg,data} → axios 响应拦截器(code==200 时取 data) → 页面
      → JwtInterceptor.afterCompletion 清理 ThreadLocal
```

### 2.2 逐个文件

#### 2.2.1 启动类

| 文件 | 关键内容 | 说明 |
| --- | --- | --- |
| `CampusTradeApplication.java` | `@SpringBootApplication` `@EnableScheduling` `@MapperScan("com.campus.trade.mapper")` | 启动入口。`@MapperScan` 让 MyBatis-Plus 为 mapper 接口生成代理实现；`@EnableScheduling` 是给 `OrderTimeoutTask` 用的，没有它定时任务不会触发 |

#### 2.2.2 `common` 包 —— 公共基础设施

| 文件 | 职责 | 关键方法/字段 |
| --- | --- | --- |
| `Result.java` | 全站统一返回体 `{code, msg, data}` | `ok(T)` / `ok()` / `fail(String)` / `fail(Integer, String)`；约定 `code=200` 为成功，前端凭这个判断 |
| `UserContext.java` | 用 `ThreadLocal<Long>` 保存「当前登录用户 id」 | `set(Long)` / `get()` / `clear()`；一次请求一个 Tomcat 线程，所以能安全存放 |
| `BizException.java` | 业务异常，可携带 code | `BizException(String)`（默认 400）、`BizException(Integer, String)`（如 403 越权） |
| `GlobalExceptionHandler.java` | `@RestControllerAdvice` 全局兜底 | `handleBiz` 原样返回业务提示；`handleValid` 取 `MethodArgumentNotValidException` 的第一条字段错误（"商品标题不能为空"这种直接给用户看）；`handleDuplicate` 把唯一键冲突转成"数据已存在，请勿重复提交"；`handleOther` 记 error 日志、只回"系统繁忙，请稍后重试"，**不把堆栈/表名泄露给前端** |
| `AdminOnly.java` | 自定义注解，标在方法或类上表示"需要管理员" | `@Target({METHOD, TYPE})` `@Retention(RUNTIME)`；由 `JwtInterceptor.needAdmin()` 读取 |

#### 2.2.3 `config` 包 —— 配置类

| 文件 | 职责 | 关键内容 |
| --- | --- | --- |
| `PasswordConfig.java` | 密码加密器 | `@Bean BCryptPasswordEncoder(10)`，强度 10（约 60~100ms/次，抗暴力破解与响应速度的平衡点） |
| `MybatisPlusConfig.java` | 分页插件 | `PaginationInnerInterceptor(DbType.MYSQL)`，`setMaxLimit(100L)` 防止前端传 `pageSize=100000` 拖垮数据库，`setOverflow(false)` 页码越界返回空而不是回第一页 |
| `WebMvcConfig.java` | Web 总装配（三件事） | ① `addInterceptors` 注册 `JwtInterceptor`，排除 `/api/user/login`、`/api/user/register`；② `addResourceHandlers` 把 `/uploads/**` 映射到磁盘 `upload.path` 目录，让上传的图片能通过 URL 访问；③ `addCorsMappings` 允许 `localhost/127.0.0.1/192.168.*.*/172.*.*.*/10.*.*.*` 的**任意端口**（`[*]`），带 `Authorization` 头，`allowCredentials(true)`；外网域名一律拒绝 |
| `SpaFallbackConfig.java` | 单页应用路由回退 | 前端用 history 模式，打包后刷新 `/goods/5` 会被浏览器直接请求到后端。这里用 `PathResourceResolver`：`/api/`、`/uploads/` 开头的不参与回退，其余找不到文件就返回 `index.html` 交给 Vue Router。**用资源解析器而不是 `@GetMapping("/**")`，是为了不把图片请求吃掉** |
| `AiProperties.java` | 大模型配置绑定 | `@ConfigurationProperties(prefix="ai")`：`apiKey` / `baseUrl`（默认智谱 `https://open.bigmodel.cn/api/paas/v4`）/ `model`（`glm-4-flash`）/ `timeout`（20000ms）；`isEnabled()` 判断 key 是否为空，空则走降级 |
| `RestTemplateConfig.java` | AI 专用 HTTP 客户端 | `SimpleClientHttpRequestFactory`：连接超时 5s、读超时取 `ai.timeout`；单独起 `aiRestTemplate` Bean，避免影响其它 HTTP 调用 |

#### 2.2.10 `service.impl` 包 —— 业务实现（重点看这里）

| 文件 | 关键实现 |
| --- | --- |
| `UserServiceImpl.java` | `register`：查重 → `passwordEncoder.encode` 存密文 → 默认 `role=0`、`status=1`。`login`：查不到用户与密码错都回同一句"用户名或密码错误"（防用户名枚举）；**渐进式迁移**——`isBcrypt()` 判断库里是 `$2a/$2b/$2y` 开头就走 `matches()`，否则按明文比对，明文成功后台回写成密文，老数据不用手工改。禁用账号抛"该账号已被禁用，请联系管理员"。`changeStatus`：禁止禁用自己、禁止操作其他管理员 |
| `GoodsServiceImpl.java` | `publish`：`userId` 只从 token 取（不信前端传的 sellerId），强制 `status=ON_SALE`、`viewCount=0`。`getDetail`：SQL 层 `view_count = view_count + 1` 自增（避免并发丢更新），拼卖家昵称/头像/校区、`mine`（是不是自己的）、`activeOrderId`（有没有进行中的订单，前端据此禁用"立即购买"）。`update/changeStatus/delete`：统一走 `getOwned(id, userId, denyMsg)` 做归属校验（本人或 role=1 管理员放行，否则 `BizException(403)`）；`STATUS_LOCKED` 的商品禁止改动。`checkPrice`：原价不得低于售价 |
| `OrderServiceImpl.java` | `create`：用**条件 UPDATE** `set status=LOCKED where id=? and status=ON_SALE`，影响行数为 0 就说明被别人抢先，直接抛"该商品已被他人下单"——这是解决并发超卖的核心，比"先查再改"可靠。订单号 `generateOrderNo()` 用时间戳 + 随机串，不复用自增主键（防止通过订单号看出成交量）。`pay` 只允许 0→1 且必须买家本人；`finish` 只允许 1→2 且必须买家本人，同时把商品置为 `SOLD`；`cancel` 允许买卖双方在 0/1 状态取消，买家取消要填原因，取消后 `releaseGoods` 把商品放回在售。`myPage` 按 `role` 决定查 `buyer_id` 还是 `seller_id`；`adminPage` 的关键词同时匹配订单号与商品标题（先查 goods id 再 `in`）。`convert/toVO` 用 `selectBatchIds` 批量取商品和用户，**避免分页列表 N+1 查询**。`cancelTimeoutOrders` 扫描超时未付款订单并回收商品 |
| `AiServiceImpl.java` | 详见 2.2.12 单独说明 |

#### 2.2.11 `task` / `utils`

| 文件 | 职责 | 要点 |
| --- | --- | --- |
| `task/OrderTimeoutTask.java` | 超时订单自动取消 | `@Scheduled(fixedDelay = 5*60*1000, initialDelay = 60*1000)`，`PAY_TIMEOUT_MINUTES = 120`。用 `fixedDelay` 而不是 `fixedRate`：上一轮跑完再等 5 分钟，避免任务堆积；`try/catch` 包住，否则一次数据库抖动会让整个调度线程停掉。答辩演示时把 120 改成 1 就能现场看自动取消 |
| `utils/JwtUtil.java` | JWT 签发与解析 | `@Value("${jwt.secret}")` / `@Value("${jwt.expire}")`；`createToken(userId)` 用 HS256，`subject` 存 userId；`parseUserId(token)` 解析失败抛异常，由拦截器转 401 |

#### 2.2.12 `service.impl/AiServiceImpl.java` —— AI 智能导购（最值得讲的模块）

结构：`chat()` 主流程 + 8 个私有方法。

| 方法 | 作用 |
| --- | --- |
| `chat(List<AiMessage>)` | Agent 主循环：最多 `MAX_ROUNDS=4` 轮。每轮把对话发给大模型，若返回 `tool_calls` 就执行工具（查库）、把 `role=tool` 的结果追加进上下文再问一次；没有工具调用就把 content 作为最终答复。最终统一过三道过滤器 |
| `searchGoodsTool()` | 工具声明（OpenAI Function Calling 格式）：`searchGoods{keyword, category, minPrice, maxPrice}`。**工具定义让模型知道"能查库"，但真正的 SQL 由 Java 执行，模型没有直接访问数据库的能力** |
| `queryGoods(JsonNode)` / `queryGoods(String,String,BigDecimal,BigDecimal)` | 把模型给的参数翻成 `LambdaQueryWrapper`：只查 `status=ON_SALE`，`keyword` 命中标题或描述，价格区间，`last("LIMIT 6")` 控制上下文长度 |
| `summarize(List<Goods>)` | 把商品列表压成精简 JSON 回给模型（只要 id/标题/价格/成色/地点），省 token、也减少模型编造字段的空间 |
| `finalText(String, List<Goods>)` | 收尾：`sanitize()` 去 Markdown，商品为空时补一句"没找到，可以放宽条件" |
| `degrade(List<AiMessage>, String)` | **降级链路**：没配 api-key 或调用异常时，取用户最后一句话做本地关键词检索，返回真实商品 + `aiUsed=false`，前端显示黄条"本次为本地关键词检索" |
| `generateDescription(...)` | 发布页的"AI 帮我写描述"：带 `DESC_PROMPT` 调模型，失败回退本地模板拼接 |
| `leakGuard(String)` | 敏感词拦截：命中 `searchgoods / tool_call / bigmodel / glm-4 / 系统提示词 / 函数名` 等就整段换成固定话术，防"告诉我你的 API"这类提示词注入泄露工具定义 |
| `guardFacts(String, List<Goods>)` | **事实校验**：用正则从回复里抽价格 `(?:价格|售价|要价|只要)[是为]?\s*[￥¥]?\s*(\d+(?:\.\d+)?)` 和成色 `[一二三四五六七八九十]成新|全新`，与工具查到的商品逐条比对；不一致就丢弃模型输出，改用 `factSummary()`（纯数据库字段拼出来的文案）。这是"模型说 300 元、库里 180 元"的兜底 |
| `sanitize(String)` | 去 `**`、`__`、反引号、`#` 标题、`-`/`*` 列表符、Markdown 链接语法、裸 URL，压缩空行（前端是纯文本渲染，不去掉会露出星号） |
| `message(...)` / `decimalArg(...)` / `conditionText(...)` / `norm(...)` | 拼消息体、安全取数值参数、成色数字转中文、价格去尾零 |

调用顺序：`chat → (runAgent 循环) → sanitize → leakGuard → guardFacts → 返回 AiChatVO{reply, goods, aiUsed}`。

## 五、三条典型调用链（论文里可直接画时序图）

**1）登录**
`Login.vue → POST /api/user/login → UserController.login(@Valid LoginDTO) → UserServiceImpl.login`
（查用户 → BCrypt `matches` → 明文则迁移 → `JwtUtil.createToken` → 组装 `LoginVO`）
`→ 前端存 token/userInfo → router.push('/goods')`

**2）下单**
`GoodsDetail.vue → POST /api/orders → JwtInterceptor(取 buyerId) → OrderServiceImpl.create`
（校验商品在售 → `UPDATE goods SET status=2 WHERE id=? AND status=1`，0 行则抛"已被抢" →
生成订单号 → 插入 `orders(status=0)` → 回 `OrderVO`）
`→ 前端跳 /orders；2 小时未付款由 OrderTimeoutTask 自动取消并释放商品`

**3）AI 导购**
`AiChat.vue → POST /api/ai/chat → AiServiceImpl.chat`
（拼 system + 历史 → 调 GLM-4-Flash 带 tools →
模型返回 `tool_calls: searchGoods` → Java 执行 SQL 查在售商品 → 结果以 `role=tool` 回传 →
模型组织语言 → `sanitize` → `leakGuard` → `guardFacts` → `AiChatVO{reply, goods, aiUsed}`）
`没配 key 或超时 → degrade() 本地关键词检索，aiUsed=false`
