## 3. 快速部署（面向答辩演示，推荐）

打包版默认使用 SQLite，无需安装数据库或 Python，开箱即用。

### 3.1 安装与启动

1. 将 `dist-electron-final/win-unpacked` 整个目录复制到目标位置（或运行安装包安装）。
2. 双击 `MusicCollection.exe` 启动客户端。
3. 客户端会自动拉起随包后端 `resources/backend/music-api.exe`，首次启动会自动建表、创建管理员并播种演示数据，约数秒后进入登录页。

### 3.2 登录

| 项目 | 值 |
| --- | --- |
| 用户名 | `admin` |
| 密码 | `admin123` |
| 角色 | 管理员（可见"管理后台"菜单） |

登录后概览页应显示：**3 个歌单 / 8 首歌曲 / 6 个标签**，最近收藏列出已录入的示例歌曲。

> 演示前请确认网络通畅：示例歌曲使用 SoundHelix 音频直链与 picsum 封面，联网可正常试听与显示；封面加载失败时界面会自动使用默认渐变封面，不影响功能演示。

## 4. 源码部署（开发/二次开发）

### 4.1 后端

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# 方式一：使用 SQLite（零配置，推荐）
# 编辑 .env：USE_SQLITE=1

# 方式二：使用 MySQL
# 编辑 .env：USE_SQLITE=0，并填写 DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME
# 导入建库脚本：mysql -u root -p < ../database/schema.sql

python init_db.py               # 可选：显式初始化数据库
python run.py                   # 启动后端，默认 http://127.0.0.1:5000/api
```

关键配置项（`.env`）：

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| `USE_SQLITE` | 1=SQLite 演示模式，0=MySQL | 源码 0 / 打包版 1 |
| `SQLITE_PATH` | SQLite 文件路径 | Electron 自动设为 `%APPDATA%/music-collection-desktop/music_collection.db` |
| `DB_*` | MySQL 连接参数 | root / 127.0.0.1:3306 / music_collection |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 初始化管理员账号 | admin / admin123 |
| `SEED_DEMO_DATA` | 是否自动播种演示数据 | 1 |
| `PORT` | 后端端口 | 5000 |

### 4.2 前端（开发模式）

```bash
cd frontend
npm install
npm run electron:dev       # 一键启动 Vite + Electron（需后端已在 5000 端口运行）
```

或仅启动前端开发服务器：

```bash
npm run dev                # http://127.0.0.1:5173
```

### 4.3 重新打包

```bash
# 后端打成单文件 exe -> backend-dist/music-api.exe
cd backend && pip install -r requirements-pack.txt && python build_backend.py

# 前端 + Electron 打包 -> dist-electron/
cd frontend && npm run pack:win
```

## 5. 数据库维护

### 5.1 演示数据重新导入

若演示数据被修改，可用项目自带的 SQL 脚本恢复（以 SQLite 为例）：

```bash
python -c "import sqlite3,os; p=os.path.join(os.environ['APPDATA'],'music-collection-desktop','music_collection.db'); c=sqlite3.connect(p); c.executescript(open('demo-data.sql',encoding='utf-8').read()); c.commit()"
```

脚本会先清空旧业务数据，再插入 6 标签 / 3 歌单 / 8 歌曲 / 16 关联，保留 admin 账号。

### 5.2 演示数据同步机制

`backend/app/demo_data.py` 是演示数据的唯一数据源：修改其中的 `TAGS/PLAYLISTS/SONGS` 后，执行 `python seed_demo.py --sync-schema` 可自动同步更新 `database/schema.sql` 的锚点区间，保证 SQL 脚本与运行时播种一致。

## 6. 使用流程

### 6.1 普通用户

1. **注册/登录**：进入应用后在登录页注册账号，或用已有账号登录。
2. **概览**：查看歌单/歌曲/标签数量及最近收藏。
3. **整理歌单**：在"我的歌单"新建歌单，点击歌单查看其中歌曲。
4. **收藏歌曲**：在"全部歌曲"点击"新增歌曲"，填写歌名、歌手、音乐链接、封面与备注，选择所属歌单并勾选标签。
5. **试听/跳转**：点"试听"在弹窗播放音频直链；点"链接"在系统浏览器打开网页链接。
6. **检索**：用关键词框或标签/歌单下拉框组合筛选歌曲。
7. **管理标签**：在"标签管理"新建彩色标签，编辑或删除；删除标签会从歌曲上同步移除。
8. **个人中心**：修改昵称、邮箱、头像或密码。

### 6.2 管理员

1. 以 `admin` 登录后侧边栏出现"管理后台"入口。
2. **平台总览**：查看全平台用户/歌单/歌曲/标签统计与最近注册用户。
3. **用户管理**：搜索用户，执行启用/禁用、设为/取消管理员、删除用户及数据。
   - 系统约束：不能禁用或删除当前登录账号；不能取消自己的管理员权限；至少保留一个启用的管理员。
4. **内容治理**：在"歌曲管理"/"歌单管理"标签页查看全部内容，删除违规歌曲或歌单（删除歌单时其中歌曲转为未分类）。

## 7. 常见问题（FAQ）

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| 客户端打开后一直"等待后端" | 后端 exe 未启动或端口被占用 | 确认 5000 端口空闲；查看 `backend-dist` 日志；手动运行 `music-api.exe` |
| 提示"无法连接服务器" | 后端服务未运行 | 启动后端；确认 `.env` 中 `PORT` 与前端请求地址一致 |
| 登录后提示"账号已被禁用" | 管理员禁用了该账号 | 联系管理员重新启用 |
| 试听按钮为灰色 | 歌曲未提供 url | 编辑歌曲，填写以 `.mp3` 等音频后缀结尾的直链 |
| 封面不显示 | 图片直链网络不通 | 联网后重试；系统会自动显示默认渐变封面 |
| 看不到"管理后台"菜单 | 当前不是管理员角色 | 使用 admin 账号登录，或让管理员提升角色 |
| 修改数据库配置后数据异常 | 配置与实际库不一致 | 确认 `USE_SQLITE`、`SQLITE_PATH`/`DB_*` 指向同一数据库 |
| 忘记管理员密码 | 密码为哈希存储，无法直接找回 | 源码环境可重新初始化并重置；或新建一个管理员账号 |

---

## 8. 安全建议

1. 演示或上线前，在"个人中心"修改默认管理员密码 `admin123`。
2. 生产环境将 `.env` 中的 `SECRET_KEY` 与 `JWT_SECRET_KEY` 改为随机强密钥。
3. 使用 MySQL 时，为应用创建独立数据库账号并限制权限，避免使用 root。
4. Token 有效期默认 7 天（可配置），到期后需重新登录。
