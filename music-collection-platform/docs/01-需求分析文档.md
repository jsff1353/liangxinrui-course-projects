## 1. 引言

### 1.1 编写目的

本文档明确"音乐收藏管理桌面平台"的业务背景、建设目标和用户需求，作为后续原型设计、系统设计、编码实现与测试验收的依据。文档面向指导教师、评审人员及项目开发人员。

### 1.2 项目背景

随着数字音乐资源的快速增长，用户常需要在多个平台之间分散地收藏喜欢的歌曲，缺乏一个本地化、条理化的管理工具。常见的音乐平台附带收藏功能，但存在广告干扰、归属平台绑定、无法自定义分类与备注等问题。本课题拟开发一款**纯净、无广告、离线可用的桌面端音乐收藏管理工具**，帮助用户以"歌单 + 标签"的方式组织私人音乐库，并提供管理员后台对平台内容进行统一维护。

### 1.3 项目目标

1. 实现一个可安装运行的桌面客户端，提供登录注册、个人音乐收藏管理、后台管理三大能力。
2. 采用前后端分离架构：Vue 3 桌面前端 + Flask REST API 后端 + 关系型数据库。
3. 支持按歌单归类、按自定义标签多维标记、关键词/标签/歌单组合检索、音频直链试听。
4. 提供面向管理员的数据总览、用户管理与违规内容治理能力。
5. 保证数据安全：密码加密存储、JWT 鉴权、用户数据隔离、越权访问拦截。

### 1.4 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| 歌单（Playlist） | 用户自定义的歌曲集合，一首歌最多归属一个歌单 |
| 标签（Tag） | 用户自定义的标记，一首歌可拥有多个标签，标签与歌曲为多对多关系 |
| JWT | JSON Web Token，用于无状态登录鉴权 |
| ORM | 对象关系映射，本项目使用 SQLAlchemy |
| REST | 表述性状态传递，一种 Web API 设计风格 |

## 2. 用户角色分析

| 角色 | 描述 | 主要权限 |
| --- | --- | --- |
| 游客 | 未登录访问者 | 注册账号、登录 |
| 普通用户 | 注册成功的音乐收藏者 | 管理本人的歌单、歌曲、标签与个人资料；查看概览统计 |
| 管理员 | 平台维护者（默认 admin） | 普通用户全部权限 + 访问管理后台：全局数据总览、用户管理、违规歌曲/歌单删除 |

角色之间通过 `users.role` 字段区分（`user` / `admin`），后端通过 `admin_required` 装饰器强制校验，前端通过路由守卫隐藏管理入口，形成双重控制。

## 4. 非功能性需求

### 4.1 安全性

- **密码安全**：用户密码经 `werkzeug` 的 `pbkdf2:sha256` 加盐哈希后存储，数据库中不保存明文。
- **身份鉴权**：除登录/注册外，全部接口需携带 JWT；后端统一校验 Token 有效性、用户存在性及启用状态。
- **权限控制**：普通用户仅能访问本人数据（`owned()` 校验归属），管理员接口独立鉴权（`admin_required`）。
- **输入校验**：所有入参做长度限制、格式校验、类型收敛与首尾空格清理，防止异常输入与越界写入。
- **级联一致性**：删除用户/标签/歌曲时由 ORM 级联清理关联数据，避免脏数据残留。

### 4.2 易用性

- 界面采用中文，界面风格统一（紫色主色调），提供空状态引导与操作确认弹窗。
- 关键破坏性操作（删除、退出、禁用）均有二次确认。
- 提供演示数据自动播种，首次登录即可看到完整示例内容，无需手工录入。

### 4.3 可靠性与可维护性

- 后端采用模块化蓝图（Blueprint）组织，前后端通过统一响应结构 `{code, message, data}` 通信。
- 支持 MySQL 与 SQLite 双模式切换，同一套 ORM 代码无需修改。
- 提供幂等的初始化与播种逻辑，重复启动不会产生重复数据。

### 4.4 运行环境约束

- 操作系统：Windows 10/11（桌面客户端），后端可跨平台。
- 前端：Electron 33 桌面壳 + 现代浏览器内核。
- 数据库：MySQL 5.7+/8.0 或 SQLite 3。

## 5. 用例描述

### 用例 UC-01：用户登录

| 项目 | 内容 |
| --- | --- |
| 参与者 | 游客 |
| 前置条件 | 已注册账号且账号处于启用状态 |
| 主流程 | 1. 进入登录页 → 2. 输入用户名与密码 → 3. 提交 → 4. 系统校验通过并签发 JWT → 5. 跳转概览页 |
| 备选流程 | 密码错误/账号禁用 → 提示对应错误信息，停留在登录页 |
| 后置条件 | 本地保存 Token 与用户信息，后续请求自动携带鉴权头 |

### 用例 UC-02：为歌曲打标签并检索

| 项目 | 内容 |
| --- | --- |
| 参与者 | 普通用户 |
| 前置条件 | 已登录，且至少已创建一个标签 |
| 主流程 | 1. 新增/编辑歌曲 → 2. 勾选标签并保存 → 3. 在歌曲页按该标签筛选 → 4. 系统返回带此标签的歌曲列表 |
| 后置条件 | `song_tags` 关联表记录更新，检索结果与标记一致 |

### 用例 UC-03：管理员禁用违规用户

| 项目 | 内容 |
| --- | --- |
| 参与者 | 管理员 |
| 前置条件 | 以管理员账号登录 |
| 主流程 | 1. 进入管理后台 → 2. 搜索目标用户 → 3. 点击"禁用" → 4. 系统更新状态并生效 |
| 备选流程 | 目标为当前登录账号 → 拒绝操作并提示 |
| 后置条件 | 被禁用用户再次请求接口时返回 403，无法访问任何业务数据 |

## 6. 需求优先级与验收标准

| 需求类别 | 优先级 | 验收标准摘要 |
| --- | --- | --- |
| 用户与认证 | 高 | 注册/登录/退出流程可用，非法输入有明确提示，密码不明文存储 |
| 歌单/歌曲/标签 CRUD | 高 | 增删改查完整，数据隔离正确，删除歌单不丢歌曲 |
| 检索与试听 | 高/中 | 三类筛选结果准确，音频直链可播放 |
| 管理后台 | 高 | 管理员可执行用户与内容治理，安全约束全部生效 |
| 概览统计 | 高 | 展示数据与数据库实际数量一致 |
