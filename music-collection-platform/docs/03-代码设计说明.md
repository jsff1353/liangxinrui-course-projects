## 2. 系统架构

```
┌─────────────────────────────────────────────┐
│  Electron 桌面客户端（渲染进程 Vue 3 SPA）      │
│  - 视图层：Login/Home/Playlists/Songs/Tags...  │
│  - 状态层：Pinia（用户状态）                    │
│  - 请求层：Axios 封装 + Token 拦截器            │
└──────────────────┬──────────────────────────┘
                   │ HTTP / JSON (REST)
┌──────────────────▼──────────────────────────┐
│  Flask 后端（music-api.exe / run.py）          │
│  - 路由层：6 个 Blueprint                      │
│  - 工具层：鉴权装饰器 / 统一响应 / 分页          │
│  - 模型层：SQLAlchemy ORM（5 张表）             │
│  - 启动层：bootstrap 建表 + 管理员 + 演示数据    │
└──────────────────┬──────────────────────────┘
                   │ SQLAlchemy ORM
┌──────────────────▼──────────────────────────┐
│  关系型数据库（SQLite 演示 / MySQL 生产）        │
└─────────────────────────────────────────────┘
```

请求处理链：`Axios(带Token) → Flask Blueprint → 装饰器鉴权 → 参数校验 → ORM 操作 → 统一响应 → 响应拦截器拆包`。

## 4. 后端核心模块设计

### 4.1 应用工厂（app/\_\_init\_\_.py）

`create_app()` 完成配置加载、扩展初始化（`db`、`jwt`、`cors`）、蓝图注册、健康检查 `/api/health`、404/405/500 错误处理及 JWT 各类加载器（未登录/过期/无效 Token 统一返回业务码）。

### 4.2 配置层（config.py）

按优先级读取 `.env`（显式路径 > exe 同目录 > 打包资源 > backend 目录）。`create_database_uri()` 依据 `USE_SQLITE` 生成 SQLite 或 MySQL 连接串；JWT 密钥、过期时间（默认 7 天）均可配置。

### 4.3 模型层（models.py）

| 模型 | 表名 | 关键字段 |
| --- | --- | --- |
| User | users | username(唯一)、password_hash、nickname、role(user/admin)、status(1/0) |
| Playlist | playlists | user_id(FK)、name、description、cover、时间戳 |
| Song | songs | user_id(FK)、playlist_id(FK,可空)、title、artist、url、cover、notes、时间戳 |
| Tag | tags | user_id(FK)、name、color，(user_id,name) 唯一约束 |
| song_tags | song_tags | song_id、tag_id 联合主键，多对多关联 |

关系与级联：删除用户级联删除其歌单/歌曲/标签；删除歌单时歌曲 `playlist_id` 置空（SET NULL）保留收藏；删除歌曲/标签自动清理 `song_tags` 关联。

### 4.4 工具层（utils.py）

| 函数 | 职责 |
| --- | --- |
| `success/error` | 统一响应结构 `{code, message, data}`，业务码与 HTTP 状态码同步 |
| `login_required` | 校验 JWT、用户存在与启用状态，挂载 `g.current_user` |
| `admin_required` | 在登录校验基础上校验 `role == 'admin'` |
| `owned` | 校验记录归属，防止越权访问他人数据（404/403） |
| `paginate` | 统一分页，返回 list/total/page/size/pages |
| `text/get_json_body` | 安全取参，去空格、容错 |

### 4.5 启动初始化（bootstrap.py + demo_data.py）

`initialize()` 在应用启动时：① 检测缺表则 `db.create_all()`；② 确保管理员账号存在（默认 `admin/admin123`）；③ 调用 `seed_demo_data()` 幂等播种演示数据（已有歌曲则跳过，不覆盖用户数据）。`demo_data.py` 同时提供 `export_insert_sql()`/`sync_schema_sql()`，使运行时数据与 `schema.sql` 保持一致。

## 5. 数据库设计

### 5.1 E-R 关系

```
User ──1:N── Playlist
User ──1:N── Song
User ──1:N── Tag
Playlist ──1:N── Song       （删除歌单 Song.playlist_id=NULL）
Song ──M:N── Tag  (经 song_tags)
```

### 5.2 表结构要点

- **users**：`username` 唯一索引；`role` 区分角色；`status` 控制启用。
- **songs**：`url` 长度 1000，支持音频直链或网页链接；`notes` 为 TEXT 备注。
- **tags**：`(user_id, name)` 唯一约束，实现"每用户独立标签字典"。
- **song_tags**：联合主键防重复关联，双外键均 ON DELETE CASCADE。

初始化脚本 `database/schema.sql` 含完整 DDL 与演示数据，锚点 `-- ==== BEGIN/END AUTO DEMO DATA ====` 之间的内容由 `demo_data.py` 自动生成，杜绝两份数据不一致。

- 前缀 `/api`；除 auth 外均需 `Authorization: Bearer <token>`。
- 成功响应：`{"code":0,"message":"...","data":...}`；失败：`{"code":非0,"message":"...","data":null}` + 对应 HTTP 状态码。

## 7. 前端核心实现

- **请求层**（`api/request.js`）：Axios 实例按环境选择 baseURL；请求拦截器注入 Token；响应拦截器拆包 `data`、统一错误提示、401 时清理本地登录态并跳转登录页。
- **接口封装**（`api/index.js`）：按 auth/user/playlist/song/tag/admin 分组导出方法，视图层只调用语义化方法。
- **状态管理**（`store/user.js`）：Pinia 保存 token、用户信息，派生 `isAdmin`，提供 login/logout/fetchMe。
- **路由守卫**（`router/index.js`）：公开页直通；受保护页校验 token；`meta.admin` 页校验角色。
- **组件复用**：`SongTable` 统一歌曲表格与试听/链接/编辑/删除操作；`SongCover` 在封面缺失时按 seed 生成渐变占位图；表单组件通过 `v-model` + 事件与父页面通信。

## 8. 关键设计说明

1. **数据隔离**：所有业务查询均带 `user_id = current_user.id`，配合 `owned()` 杜绝水平越权。
2. **试听判定**：前端以 URL 是否以音频后缀结尾决定"试听/链接"按钮可用性；音频直链在弹窗中 `<audio>` 播放，网页链接交给 Electron 调用系统浏览器。
3. **删除歌单不丢数据**：以 `UPDATE songs SET playlist_id=NULL` 保留收藏，体现"歌单只是分类容器"的设计思想。
4. **幂等播种**：重复启动不产生重复数据，且尊重用户已有收藏，适合演示与教学场景。
5. **演示数据与脚本同源**：`demo_data.py` 单一数据源同时驱动运行时播种与 `schema.sql`，避免不一致。
